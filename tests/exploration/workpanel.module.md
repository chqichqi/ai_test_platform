## 关键元素

### 患者档案列表（跳转目标）
- 分页总数：`.ant-pagination-total-text` 文本格式 `共N条记录`
- 表头列：姓名 / 编号 / 手机号码 / 性别 / 年龄 / 绑定设备 / **录入时间** / 随访项目 / 疾病标签 / 异常事件 / 备注 / 操作
- 疾病筛选标签：`.ant-tag` 元素，含疾病名文本
- URL 查询参数：`?exceptionType=<diseaseCode>`
- 疾病代码映射（部分实测）：
  - 室早 → `ventricularPremature`
  - 房颤 → `atrialFibrillation`
  - 心动过速 → `tachycardia`
  - 持续性房颤 → `persistent_af`

### 预警卡片
- 标题文本格式：`<名称>` 或 `<名称>(N)` / `<名称> (N)`
- 无数据形式：① 显示「暂无数据」文本；② 标题带 `(0)`；③ 仅有标题/下拉控件无数据行
- 卡片内常见控件：下拉「全部」、标签页「图表」「列表」（仅房颤预警，**当前 tt 环境账号未观察到此 tab，仅有列表视图**）

### 预警过滤下拉框（已实测 tt 环境）

| 卡片 | 下拉选项 | 对应 API 参数 | 调用接口 |
|---|---|---|---|
| 房颤预警 | 全部 / ≥10 / ≥20 / ≥30 / ≥40 / ≥50 | 全部=不带参数或 `afLoad=`（空值）；其余 `afLoad=10\|20\|30\|40\|50` | `GET /hospital/newPanel/afLoad?pageNo=0&pageSize=20[&afLoad=N]` |
| 佩戴预警 | 全部 / 未发送 / 已发送 | 全部=不带参数或 `smsSendStatus=`（空值）；未发送 `smsSendStatus=0`；已发送 `smsSendStatus=1` | `GET /hospital/newPanel/ppg-wear-warning?pageNo=0&pageSize=10[&smsSendStatus=0\|1]` |
| 测量预警 | 全部 / 未发送 / 已发送 | 全部=不带参数或 `smsSendStatus=`（空值）；未发送 `smsSendStatus=0`；已发送 `smsSendStatus=1` | `GET /hospital/newPanel/measure-warning?pageNo=0&pageSize=10[&smsSendStatus=0\|1]` |

> **注**：首次加载时「全部」对应**不带过滤参数**；当用户从其他选项切回「全部」时，前端会发送**空值**的过滤参数（如 `smsSendStatus=`、`afLoad=`），两者在后端均视为不过滤。

下拉框 DOM 结构：
- 使用 ant-design `Select` 组件
- 触发器：卡片标题右侧的 `.ant-select-selector`，默认显示文本「全部」
- 弹出层：`.ant-select-dropdown:not(.ant-select-dropdown-hidden) .ant-select-item-option`
- 选项命中后会立即触发对应 API 重新拉取列表数据并刷新右上角 `(N)` 计数（房颤预警卡片无 (N) 显示）

## 业务流程（SKILL §工作台模块）

### 指标总览卡片点击
1. 读取卡片 `总数` 与 `今日新增` 文本
2. 点击卡片 → 跳转到对应业务页（按上表）
3. 断言：
   - 患者人数：列表 `共N条记录` 数 = 卡片总数；`录入时间`=今天 的行数 = 卡片今日新增
   - 疾病卡片：URL 含 `?exceptionType=`，且筛选区可见疾病名标签
   - 审核/物流/随访：表格记录总数 = 卡片新增数
4. **`page.go_back()` 返回工作台**

### 预警卡片点击
1. 卡片有数据时：取第一行患者标识 → 点击 → 跳转患者详情
2. 断言（详情页中可看到原患者标识）→ 返回工作台
3. 无数据时直接 skip

### 预警过滤下拉框（房颤/佩戴/测量）
1. **存在性前置检查**：每个预警卡片标题右侧必须存在 `.ant-select-selector`，默认值为「全部」
2. **选项断言**：
   - 房颤预警：选项必须为 `["全部","≥10","≥20","≥30","≥40","≥50"]`
   - 佩戴预警 / 测量预警：选项必须为 `["全部","未发送","已发送"]`
3. **切换有效性**（API 拦截）：
   - 选择非「全部」项后，对应接口必须重新发起一次请求，且 query 包含正确参数
     - 房颤预警：`afLoad=10|20|30|40|50`
     - 佩戴/测量：`smsSendStatus=0`（未发送）或 `1`（已发送）
   - 选择「全部」时，参数必须**不带** `afLoad` / `smsSendStatus`
4. **UI 反馈**：
   - 选中项在下拉触发器内回显（如「≥10」「已发送」）
   - 列表区按新条件刷新；若无匹配则显示「暂无数据」
   - 房颤预警卡片标题不带 (N)；佩戴/测量预警卡片标题 (N) 数随过滤变化
5. **测试完毕后还原**：将下拉选项切回「全部」，避免影响后续用例
