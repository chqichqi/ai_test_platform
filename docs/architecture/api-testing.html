  • 支持 URL 或文件 导入 Swagger/OpenAPI，解析出接口、参数、响应 schema。
  • 接口列表、Tag 分类、用例与版本、环境管理一应俱全。
🧠

AI 生成用例

  • 识别接口依赖关系，自动识别业务流（request→confirm 等）建立前置依赖。
  • 生成 正常 / 异常 / 边界 场景，断言规则智能生成。

  • 执行时取项目级 api_auth（登录模块/探索捕获联动保存），运行时注入 token。

3实现链路与机制

主链路四段：导入 → 解析 → 生成 → 执行。

① 导入与解析

  • ◗ 支持 Swagger URL / 上传文件；解析出接口、请求/响应 schema、Tag、参数类型。
  • ◗ 解析时处理 $ref 引用、可选字段(anyOf/null)、表单格式 等 OpenAPI 细节，避免字段缺失。

② AI 生成（关键机制）

依赖识别

  • 识别接口路径中的业务流模式（request→confirm、send→verify…）自动建立前置依赖。
  • 对前置接口配置变量提取（token/code/id…），后续接口用 ${var} 引用。
  • 执行时拓扑排序：无依赖的先跑，前置登录第一个执行。

用例与断言

  • 每条接口生成 正常 / 异常 / 边界 用例；正常用例带响应字段断言。
  • 断言规则从 Swagger responses 动态取状态码，不写死硬编码状态。
  • 认证类接口适配 OAuth2 表单格式；用例加随机用户名避免重复注册冲突。

③ 执行

  • ◗ 用 httpx 实际请求目标系统；单条与批量执行；执行后落库执行记录。
  • ◗ 每步按用例 spec/参数 组装 query/path/header/body 并发送。

4鉴权注入与测试数据

🔐

运行时鉴权

  • 项目级 api_auth（由登录模块/探索 API 捕获联动保存）：记录鉴权形态（Bearer 注入头/前缀、cookie、api key）。
  • 执行前 _execute_auth_config 实时取 token → 注入请求头，不把口令明文落库（敏感字段替换为占位符）。
  • 提供 测试鉴权 /test-auth 端点验证配置是否可用。
🧪

测试数据（与 UI 共用 Manager）

  • API 用例的 materialize_api_case 用 TestDataManager 实例化数据计划 → 组装请求数据。
  • 正常用例保留探索时的真实值；异常/边界用例用 mutation 确定性生成错误值（类型错误/缺字段/不存在资源/越界…），不靠 LLM 临场编。
  • 一次运行的随机值不写回用例，保持用例可复用。
一句话：API 测试 = 从 Swagger 导入 → AI 识别依赖并生成 正常/异常/边界 用例 → httpx 执行 → 项目级鉴权运行时注入 + 共用数据体系。已能作为独立入口跑通接口回归。

5执行中心 · API 场景测试（已接通）

执行中心支持 UI / API / 压力 三类场景；API 场景可将 API 用例编入并在执行中心一键执行，结果按通过/失败/跳过汇总。

🗂

场景编排

  • 创建 API 类型场景（scene_type=api），把 API 用例加入、拖拽排顺序、单条启停。
  • 场景按项目组织；条目沿用 wui/case_id 绑定，展示名在场景详情里解析显示。
▶

场景执行（复用 API 执行链路）

  • 执行时收集场景内 API 用例，复用 API 批量执行链路：拓扑排序（含自动补 depends_on 前置如登录）→ 项目环境/项目级运行时鉴权 → 每条 httpx 执行。
  • 结果并入场景统计：通过 / 失败 / 错误 / 跳过，并按执行顺序展示。
  • 与 API 测试独立入口同源同行为（共用同一套执行函数与数据体系），不另起炉灶。
结论：API 场景测试链路已接通——从"把 API 用例编成场景"到"执行中心一键跑"，复用 API 自身的拓扑/鉴权/httpx 执行能力，实现 UI 与 API 场景的统一编排执行。
