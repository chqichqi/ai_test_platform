## 功能详情

### 1. 版本删除操作 ✅

**功能说明**:
- 支持删除规划中状态的版本
- 其他状态的版本不可删除，防止误操作
- 删除版本时会级联删除关联的需求文档

**后端 API**:
```
DELETE /api/v1/versions/{version_id}
```

**前端实现**:
- 版本列表中显示删除按钮（仅规划中状态可见）
- 删除前有确认对话框
- 删除后自动刷新列表

**位置**:
- 后端：`backend/app/api/api_v1/endpoints/versions.py:254-271`
- 前端：`frontend/src/pages/projects/ProjectDetailPage.tsx:232-241`

**API 端点** (`backend/app/api/api_v1/endpoints/versions.py:23-103`):

### 3. 保存版本时自动生成测试用例和 XMind ✅

**功能说明**:
- 创建版本后自动调用 LLM+SKILL 模板
- 生成结构化功能测试用例
- 生成 XMind 思维导图（OPML 格式）
- 生成过程异步执行，不影响版本创建

**核心服务** (`backend/app/core/services/version_generator.py`):

**主要方法**:
- `generate_test_assets()`: 主入口，协调整个生成流程
- `_build_system_prompt()`: 根据 SKILL 模板构建系统提示词
- `_build_user_prompt()`: 构建用户提示词
- `_parse_llm_response()`: 解析 LLM 的 JSON 响应
- `_save_test_cases()`: 保存测试用例到数据库
- `_generate_xmind_opml()`: 生成 OPML 格式的思维导图
- `_save_xmind()`: 保存思维导图到数据库

**生成流程**:
```
1. 获取功能测试 SKILL 模板
   ↓
2. 构建系统提示词和用户提示词
   ↓
3. 异步调用 LLM 生成测试用例
   ↓
4. 解析 LLM 的 JSON 响应
   ↓
5. 批量保存测试用例到数据库
   ↓
6. 生成 XMind 思维导图（OPML 格式）
   ↓
7. 保存思维导图到数据库
```

**API 端点**:

**自动触发** (创建版本时):
```
POST /api/v1/versions/?auto_generate=true
```

**手动触发**:
```
POST /api/v1/versions/{version_id}/generate-assets
```

**返回示例**:
```json
{
  "success": true,
  "message": "测试资产生成成功",
  "data": {
    "success": true,
    "test_cases_count": 25,
    "xmind_count": 1,
    "analysis_summary": {
      "total_count": 25,
      "p0_count": 5,
      "coverage_analysis": "覆盖所有主要功能点",
      "risk_points": ["登录安全性", "数据一致性"]
    }
  }
}
```

**前端集成**:
- 创建版本时默认启用自动生成（`auto_generate=true`）
- 创建成功后显示生成进度和结果
- 支持手动重新生成

### 4. 需求文档更新及测试用例自动更新 ✅

**功能说明**:
- 支持更新已上传的需求文档
- 更新后可选重新生成测试用例
- 支持增量更新（保留原有测试用例）

**使用场景**:
- 需求微调后需要更新测试用例
- 需求文档有错误或遗漏需要补充

**API 端点** (`backend/app/api/api_v1/endpoints/requirements.py:199-267`):
```
POST /api/v1/requirements/{doc_id}/update-and-regenerate
```

**请求参数**:
```json
{
  "content": "更新后的需求文档内容",
  "name": "可选：新文档名称"
}
```

**查询参数**:
- `regenerate=true/false`: 是否重新生成测试用例（默认 true）

**返回示例**:
```json
{
  "success": true,
  "message": "需求文档更新成功，测试用例已重新生成",
  "data": {
    "document_updated": true,
    "regenerated": true,
    "test_cases_count": 30,
    "xmind_count": 1,
    "analysis_summary": {
      "total_count": 30,
      "p0_count": 6,
      "coverage_analysis": "覆盖所有主要功能点和新增需求",
      "risk_points": ["登录安全性", "数据一致性", "新增的权限控制"]
    }
  },
  "document": {
    "id": 123,
    "name": "用户管理模块需求文档",
    "content": "...",
    "status": "parsed",
    ...
  }
}
```

**前端 API** (`frontend/src/api/requirementApi.ts:111-116`):
```typescript
updateAndRegenerate: async (
  id: number, 
  data: { content?: string; name?: string }, 
  regenerate: boolean = true

```

## 使用指南

### 创建版本并自动生成测试用例

**步骤**:
1. 进入项目详情页
2. 点击"创建版本"按钮
3. 填写版本信息（版本号、版本名称、描述、计划时间）
4. **必填**：在"需求文档"输入框粘贴评审通过的需求文档
5. 点击"确定"
6. 系统自动创建版本和需求文档
7. 系统自动调用 LLM+SKILL 生成测试用例和思维导图
8. 查看生成结果（测试用例数、思维导图数）

**注意**:
- 需求文档内容不能为空
- 建议使用 Markdown 格式，结构清晰
- 生成过程需要 10-30 秒，请耐心等待

### 手动触发资产生成

如果创建版本时禁用了自动生成，可以手动触发：

```bash
curl -X POST http://localhost:8008/api/v1/versions/{version_id}/generate-assets
```

### 更新需求文档并重新生成测试用例

**步骤**:
1. 找到版本关联的需求文档
2. 调用 `updateAndRegenerate` API
3. 传入更新后的需求文档内容
4. 系统自动更新文档并重新生成测试用例
5. 查看生成结果

**注意**:
- 新测试用例会追加到现有列表，不会删除旧用例
- 如果需要清理旧用例，请先手动删除

## 已知限制

1. **LLM 依赖**: 需要配置有效的 LLM 服务
2. **生成时间**: 大文档生成可能需要 30 秒以上
3. **格式要求**: LLM 响应必须为 JSON 格式，否则解析失败
4. **测试用例重复**: 多次生成可能导致测试用例重复，需要手动清理
